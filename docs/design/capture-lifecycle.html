Phase ① — Pending · Provision

Capture service spin-up

  1. User applies TrafficCapture CR. If spec.capture.duration is set and already elapsed, controller immediately transitions to Completed.
  2. Controller adds finalizer capture.gateway.io/cleanup first, then validates CaptureStorage is Ready — sets phase Failed if not found, requeues 10s if not ready.
  3. createOrUpdate Deployment ({tc.Name}-capture-agent), ClusterIP Service (:8080 HTTP, :9090 gRPC), and CPU-based HPA (1–10 replicas). All owned by the CR via SetControllerReference.
  4. Mirror filter is injected in the same reconcile loop, after workloads — not on a separate pass.
  5. Status updated: phase = Active when readyReplicas > 0, else Pending. Controller requeues every 30s.
Phase ① → ② — Mirror inject · Active

RequestMirror filter injection

  1. Controller calls AddMirrorFilter() dispatching on targetRef.Kind: HTTPRoute or GRPCRoute.
  2. Fetches the Route, then iterates every rule — each rule gets its own mirror filter appended to filters[].
  3. Per-rule idempotency: hasHTTPMirrorFilter() checks backendRef.Name == "{tc.Name}-capture-agent" before appending. No-op if already present.
  4. Calls cl.Update() on the Route. Sets annotation capture.gateway.io/traffic-capture: namespace/name. Both HTTP and GRPCRoute mirrors use port 8080.
  5. Gateway controller (Envoy etc.) picks up the updated Route and starts duplicating requests fire-and-forget to the agent Service.
Phase ③ — Teardown · Finalizer

Finalizer-guarded mirror removal

  1. Triggered by kubectl delete or spec.capture.duration expiry. API server sets deletionTimestamp; finalizer blocks GC.
  2. Reconciler detects non-zero deletionTimestamp → calls reconcileDelete().
  3. Calls RemoveMirrorFilter(): iterates all rules, strips matching RequestMirror filters by agent service name, deletes annotation, calls cl.Update(). Errors are logged but non-fatal — cleanup always continues.
  4. Calls controllerutil.RemoveFinalizer() then r.Update(). Kubernetes GC cascades deletion of owned Deployment, Service, and HPA.
  5. CR is fully deleted. In-flight BufferedWriter batches are flushed by the agent pod during its own graceful shutdown.
